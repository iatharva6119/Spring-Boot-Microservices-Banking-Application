POST /api/users/register — This is the only public endpoint (permitAll). All others require a valid JWT.
1
Client sends POST /api/users/register
JSON body: { firstName, lastName, emailId, password, contactNumber }. This path is explicitly permitAll() in SecurityConfig.

Istio Ingress Gateway → banking-gateway
Request enters istio-ingressgateway on port 80. VirtualService api-gateway-route routes all prefix "/" to api-gateway.banking.svc.cluster.local:8080.
Istio GatewayVirtualServicetimeout: 15s
ISTIO_MUTUAL mTLS

API Gateway receives request
SecurityConfig.securityWebFilterChain checks: path matches /api/users/register → permitAll(). OAuth2 resource server JWT validation is SKIPPED for this path. Spring Cloud Gateway routes to lb://user-service via Eureka.

HTTP via Eureka load balancer

User Service — UserController.createUser()
UserServiceImpl.createUser() is invoked. It first calls keycloakService.readUserByEmail() to check for duplicates. If unique, creates a Keycloak UserRepresentation and calls keycloakService.createUser().

Keycloak creates user in banking-service realm
Keycloak returns HTTP 201. User Service then reads back the user from Keycloak to get the assigned auth ID. Saves User entity to MySQL user_service DB with status PENDING.

🔐 Authentication Flow
OAuth2 Authorization Code flow through Keycloak for all protected endpoints.
1
Client sends request without valid token
API Gateway SecurityConfig: anyExchange().authenticated() — gateway redirects to Keycloak authorization endpoint.
Unauthenticatedoauth2Login()
Redirect → Keycloak auth endpoint
2
Keycloak — banking-service realm
Keycloak at http://host.docker.internal:8571. Client: banking-service-client (API Gateway), banking-service-api-client (User Service admin). Realm: banking-service. User logs in, Keycloak issues authorization code.
Keycloak :8571banking-service realm
Auth code → token exchange
3
API Gateway exchanges code for JWT
Token endpoint: /realms/banking-service/protocol/openid-connect/token. JWT validated via JWK Set URI: /realms/banking-service/protocol/openid-connect/certs.
JWT RS256openid scope
JWT in Authorization: Bearer header
4
Protected API access granted
Client includes JWT in all subsequent requests. API Gateway validates JWT on every request. User status must be APPROVED in Keycloak (enabled=true) for tokens to work.
